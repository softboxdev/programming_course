1. Почему для SELECT не нужен commit(), а для INSERT — нужен?
commit() фиксирует транзакцию — то есть изменения данных. SELECT ничего не меняет, поэтому фиксировать нечего. INSERT/UPDATE/DELETE меняют данные, и без commit() изменения останутся в незавершённой транзакции (и могут откатиться при закрытии соединения).

Важно: SELECT всё равно выполняется внутри транзакции (в SQLite — неявной), просто её результат не требует фиксации. В некоторых СУБД для чтения тоже нужен COMMIT/ROLLBACK, чтобы закрыть транзакцию и снять блокировки — но не для «сохранения» данных.

2. Что вернёт fetchone(), если в таблице нет строк?
None. Именно поэтому после row = cur.fetchone() пишут if row is None: — а не if not row, потому что строка-кортеж с нулями/пустыми значениями тоже «ложна» в некоторых контекстах.

3. fetchone() vs fetchall()
fetchone() — возвращает одну строку (кортеж) или None. Экономит память.

fetchall() — возвращает список всех строк. Удобно, но грузит всё в память.

Есть ещё fetchmany(n) — порциями.

Когда что:

Ожидаешь 0 или 1 строку (поиск по id, LIMIT 1) → fetchone().

Нужны все строки и их немного → fetchall().

Строк много / неизвестно сколько → итерируй курсор (for row in cur:) или fetchmany().

4. Почему (title,) — кортеж, а (title) — нет?
Кортеж задаётся запятой, а не скобками. (title) — это просто title в скобках (группировка). (title,) — кортеж из одного элемента.

Это критично для параметризованных запросов: cur.execute("... WHERE id = ?", (id,)) — второй аргумент должен быть последовательностью. Если передать (id), это просто число, и драйвер может выдать ошибку или повести себя не так.

5. Что вернёт cursor.rowcount после UPDATE, если такого id нет?
0 — потому что ни одна строка не была изменена. (В SQLite rowcount для UPDATE/DELETE показывает число затронутых строк.)

6. Зачем isdigit() перед int(input())?
Чтобы не словить ValueError на нечисловом вводе. int("abc") бросит исключение, а "abc".isdigit() вернёт False — можно вежливо попросить ввести заново.

Нюансы: isdigit() вернёт True для некоторых юникод-цифр (например, "²"), которые int() не примет. Надёжнее try/except ValueError или str.isascii() and str.isdigit(). Плюс isdigit() не пропускает -5 и " 42 " (пробелы).

7. Как параметризованные запросы защищают от SQL-инъекции?
При cur.execute("... WHERE name = ?", (user_input,)) значение передаётся отдельно от текста SQL. Драйвер сам экранирует/квотирует его и подставляет как данные, а не как код.

При конкатенации "... WHERE name = '" + user_input + "'" ввод вроде ' OR '1'='1 становится частью SQL-синтаксиса и меняет логику запроса. Параметризация делает такое невозможным: строка ' OR '1'='1 останется просто строкой-значением для сравнения.

Правило: никогда не склеивай пользовательский ввод в SQL; для идентификаторов (имён таблиц/колонок), которые нельзя параметризовать, используй белый список.
