 Что будет, если убрать conn.commit()?
Зависит от того, как закрывается соединение и какая СУБД/настройки:

В sqlite3 (Python, по умолчанию):

INSERT/UPDATE/DELETE выполнятся, но останутся в незафиксированной транзакции.

Если в конце скрипта conn.close() — изменения откатятся (rollback при закрытии незавершённой транзакции). Данных в файле не будет.

Если процесс упадёт/убьют — тоже откат.

Пока соединение живо, изменения видны в этом же соединении (можно SELECT и увидеть их), но не видны другим соединениям.

Нюансы:

В некоторых драйверах (например, с isolation_level=None в sqlite3 — autocommit) каждый запрос коммитится сам, и commit() не нужен.

В PostgreSQL при закрытии без commit — тоже откат.

Частая ловушка: скрипт отработал «успешно», а в базе ничего нет — именно из-за забытого commit().

Итог: без commit() изменения не сохранятся на диск (при штатном закрытии соединения).

2. connection vs cursor
connection — соединение с базой: транзакции (commit/rollback), настройки, создание курсоров, закрытие. Это «канал» к БД.

cursor — объект, через который выполняются запросы и читаются результаты (execute, fetchone, fetchall, rowcount). Это «указатель» внутри соединения, который держит состояние запроса и позицию в результате.

Зачем оба:

Одно соединение можно использовать многократно и из него создавать несколько курсоров (в т.ч. для разных запросов, в т.ч. вложенных — например, читаешь курсором A, а курсором B делаешь INSERT).

Транзакция принадлежит соединению (не курсору), поэтому commit() — на conn.

Курсор — «расходник»: его создают под запрос и закрывают; соединение живёт дольше.

Аналогия: соединение — это телефонный звонок в банк, курсор — конкретный разговор/запрос в этом звонке.

3. Почему id INTEGER PRIMARY KEY заполняется сам?
В SQLite INTEGER PRIMARY KEY — это алиас для rowid, встроенного 64-битного идентификатора строки. Если значение не указано, SQLite автоматически присваивает rowid = (максимальный существующий + 1) (точнее — следующий свободный, обычно max+1).

Важно: автоинкремент именно для INTEGER PRIMARY KEY (именно такое написание — INTEGER, не INT). Если добавить AUTOINCREMENT, гарантируется монотонно возрастающий id без переиспользования удалённых (ценой небольшого оверхеда). Без AUTOINCREMENT id удалённой последней строки может быть переиспользован.

4. DEFAULT 'new' в колонке status
Это значение по умолчанию: если в INSERT не указать status, СУБД подставит строку 'new'.

sql
INSERT INTO tasks (title) VALUES ('Купить хлеб');
-- status автоматически станет 'new'
Если указать явно (INSERT INTO tasks (title, status) VALUES (..., 'done')) — используется указанное. DEFAULT не срабатывает при UPDATE и не мешает вставлять NULL явно (если колонка допускает NULL).

5. Где физически лежат данные таблицы tasks?
В SQLite вся база — один файл на диске (например, tasks.db), который вы указали в sqlite3.connect("tasks.db"). Внутри этого файла хранятся все таблицы, индексы и служебные структуры; отдельного файла на таблицу нет.

Детали:

Если в connect() передать ":memory:" — база целиком в RAM, на диске ничего нет.

Файл появляется при первом connect()/записи; путь — относительно текущей рабочей директории (или абсолютный, если указан).

В отличие от, скажем, MySQL/PostgreSQL (сервер + отдельные файлы/табличные пространства), SQLite — встраиваемая БД «в одном файле».
