# Лекция: Основы программирования на платформе «1С:Предприятие 8»

**Тема:** Встроенный язык, контексты выполнения, объектная модель и работа с данными.

**Цель:** Сформировать понимание того, как устроен код в 1С, где он выполняется, какими объектами оперирует программист и как получать данные из базы.

---

## 1. Встроенный язык: ключевые определения

**Встроенный язык «1С:Предприятие»** — это предметно-ориентированный язык программирования, предназначенный для описания алгоритмов работы прикладного решения . Он не является аналогом какого-либо классического языка, хотя имеет сходство с Pascal и Visual Basic.

### 1.1. Главные особенности

*   **Мягкая типизация:** Тип переменной определяется значением, которое в ней хранится, и может меняться в процессе работы. Объявлять переменные заранее не обязательно .
*   **Предварительная компиляция:** Перед исполнением модули преобразуются во внутренний код и кэшируются в памяти .
*   **Отсутствие программного описания объектов конфигурации:** Разработчик не создает классы справочников или документов кодом. Он использует объекты, которые были созданы визуально в Конфигураторе .
*   **Русскоязычный синтаксис:** Все ключевые слова и имена методов имеют русское написание (например, `Если`, `Тогда`, `КонецЕсли`), что снижает порог входа.

### 1.2. Событийная ориентированность

Код в 1С не выполняется линейно «от начала до конца». Он запускается платформой в ответ на **события**. Программист пишет обработчики событий: например, процедура `ПриЗаписи` в модуле документа выполнится тогда, когда пользователь нажмет «Записать» . Это ключевое отличие от написания обычных консольных программ.

## 2. Контексты выполнения: Клиент и Сервер

Одно из самых важных понятий для начинающего 1С-программиста — **контекст**. Это набор доступных функций, свойств и объектов в конкретном месте кода .

Поскольку 1С работает в клиент-серверной архитектуре, код может выполняться в двух основных средах:

| Характеристика | Клиентский контекст | Серверный контекст |
| :--- | :--- | :--- |
| **Где выполняется** | На компьютере пользователя (тонкий/толстый клиент) | В кластере серверов 1С |
| **Что доступно** | Интерфейсные объекты (формы, элементы управления), диалоги с пользователем | Прямой доступ к базе данных (чтение, запись), тяжелые вычисления |
| **Чего нет** | Прямого доступа к таблицам БД (нельзя просто так прочитать справочник) | Объектов интерфейса (нельзя показать всплывающее окно напрямую) |
| **Директивы** | `&НаКлиенте` | `&НаСервере`, `&НаСервереБезКонтекста` |

**Правило:** Если вам нужно прочитать или записать данные в базу, вы должны вызвать серверную процедуру из клиентского кода. На клиенте доступны только данные, уже загруженные в форму .

## 3. Объектная модель: Как 1С представляет данные

В 1С существует строгая иерархия программных объектов, через которые программист взаимодействует с данными. Понимание этой иерархии — половина успеха в программировании.

### 3.1. Менеджер (Manager)

**Определение:** Объект, который обеспечивает доступ к прикладному объекту как к множеству (всему справочнику, всем документам). Вы обращаетесь к нему через глобальный контекст: `Справочники.Номенклатура`, `Документы.ПриходнаяНакладная` .

**Что умеет:**
*   Создавать новые элементы: `СоздатьЭлемент()`.
*   Искать существующие: `НайтиПоКоду()`, `НайтиПоНаименованию()`.
*   Получать пустую ссылку: `ПустаяСсылка()`.

### 3.2. Ссылка (Ref)

**Определение:** Уникальный идентификатор конкретной записи в базе (конкретного элемента справочника или конкретного документа). Ссылка позволяет **только читать** данные. Изменить что-либо через ссылку нельзя .

**Пример:** В реквизите документа хранится не сам товар, а ссылка на элемент справочника «Номенклатура». Программист может прочитать название товара через `Ссылка.Наименование`, но не может изменить его.

### 3.3. Объект (Object)

**Определение:** Объект, который позволяет **изменять** данные и записывать их в базу. Чтобы получить объект для редактирования, нужно у ссылки вызвать метод `ПолучитьОбъект()` .

**Ключевые методы:**
*   `Записать()` — сохраняет изменения в базу.
*   `Удалить()` — помечает на удаление или удаляет.

**Схема работы:**
`Ссылка = Справочники.Номенклатура.НайтиПоНаименованию("Товар");`
`Объект = Ссылка.ПолучитьОбъект();`
`Объект.Цена = 100;`
`Объект.Записать();`

### 3.4. Выборка (Selection)

**Определение:** Объект для последовательного перебора записей (например, всех элементов справочника). В отличие от менеджера, выборка не загружает все данные в память сразу, а читает их по одной записи .

**Метод:** `Следующий()`.

## 4. Работа с данными: Язык запросов

Для эффективного получения данных из базы используется не перебор выборок, а **язык запросов**. Это отдельный синтаксис, похожий на SQL, который позволяет серверу базы данных выполнить выборку максимально быстро.

### 4.1. Реальные и Виртуальные таблицы

В запросах 1С таблицы делятся на два типа :

*   **Реальные таблицы:** Соответствуют физическим таблицам в базе данных. Пример: `Справочник.Номенклатура` (таблица со всеми реквизитами).
*   **Виртуальные таблицы:** Не существуют в базе в явном виде. Они формируются платформой на лету на основе реальных таблиц. Пример: `РегистрНакопления.ТоварыНаСкладах.Остатки()`. Виртуальная таблица остатков берет движения из регистра и вычисляет сальдо на нужную дату.

### 4.2. Главное правило производительности

Условия отбора для виртуальных таблиц нужно передавать **в параметры самой виртуальной таблицы**, а не в секцию `ГДЕ`.

**Плохо (медленно):**
```sql
ВЫБРАТЬ ... ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки() ГДЕ Склад = &Склад
```
В этом случае платформа сначала рассчитает остатки по **всем** складам, а потом отфильтрует один.

**Хорошо (быстро):**
```sql
ВЫБРАТЬ ... ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки(, Склад = &Склад)
```
Платформа сразу рассчитает остатки только по нужному складу .

## 5. Универсальные коллекции значений

Помимо прикладных объектов (справочников, документов), встроенный язык имеет набор вспомогательных типов для манипуляции данными в памяти :

*   **Массив:** Упорядоченный список элементов, доступ по индексу (начинается с 0).
*   **Структура:** Набор пар «Ключ (строка) — Значение». Удобно для передачи набора параметров в функцию.
*   **Соответствие:** То же, что структура, но ключом может быть значение любого типа, а не только строка.
*   **СписокЗначений:** Коллекция для работы с интерфейсами (например, для заполнения выпадающего списка на форме).

## 6. Передача параметров: По ссылке и По значению

При вызове процедур и функций в 1С по умолчанию работает передача **по ссылке**. Это значит, что если вы передали переменную в процедуру и изменили ее там, она изменится и в вызывающем коде .

Чтобы защитить переменную от изменений, используется ключевое слово **`Знач`** перед именем параметра. В этом случае передается копия значения (для примитивных типов) или копия ссылки на объект (для коллекций, что означает, что саму коллекцию можно изменить, но нельзя переприсвоить переменную) .

**Пример:**
```bsl
Процедура Тест()
    А = 10;
    ИзменитьПоСсылке(А); // А станет 20
    ИзменитьПоЗначению(А); // А останется 20 (изменения внутри не повлияют)
КонецПроцедуры

Процедура ИзменитьПоСсылке(Параметр)
    Параметр = 20;
КонецПроцедуры

Процедура ИзменитьПоЗначению(Знач Параметр)
    Параметр = 30;
КонецПроцедуры
```

## Резюме

1.  **Код в 1С** пишется на русскоязычном языке с мягкой типизацией и запускается по событиям.
2.  **Контекст** определяет, где выполняется код: на клиенте (интерфейс) или на сервере (данные). Это разделение критично для архитектуры.
3.  **Объектная модель** построена на связке: Менеджер (доступ к списку) → Ссылка (чтение) → Объект (запись).
4.  **Запросы** — основной инструмент получения данных. Для виртуальных таблиц условия нужно передавать в параметры, а не в `ГДЕ`.
5.  **Параметры** по умолчанию передаются по ссылке; использование `Знач` создает копию.
