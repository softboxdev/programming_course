# Лекция по основам 1С:Предприятие 8

**Тема:** Базовые понятия платформы, архитектура, объекты конфигурации и механизмы работы.

**Цель:** Сформировать целостное понимание того, что такое «1С:Предприятие», как устроена эта система и из каких элементов состоит прикладное решение.

---

## 1. Фундаментальное разделение: Платформа и Конфигурация

Ключ к пониманию 1С лежит в разделении системы на две сущности: **технологическую платформу** и **прикладное решение (конфигурацию)**. Это разделение является основополагающим.

### 1.1. Технологическая платформа

**Определение:** Технологическая платформа — это среда исполнения приложения и набор инструментов для его разработки и администрирования . Сама по себе платформа не является программой для конечного пользователя (бухгалтера, менеджера). Она представляет собой «движок» и конструктор.

Платформа содержит:
*   Среду исполнения (клиентские приложения, сервер).
*   Средства разработки (Конфигуратор).
*   Механизмы администрирования (управление пользователями, резервное копирование).

Платформа решает задачи производительности, эргономики и предоставляет разработчику готовые «кирпичи» для построения учета .

### 1.2. Конфигурация (Прикладное решение)

**Определение:** Конфигурация — это прикладное решение, разработанное на данной платформе для автоматизации конкретной области деятельности (например, бухгалтерского учета, торговли, управления персоналом) .

Конфигурация не пишется «с нуля» на языке программирования. В её основе лежат **метаданные** — структурированное описание объектов предметной области. Разработчик описывает, какие справочники нужны, какие документы создаются, как они связаны, а платформа на основе этого описания автоматически генерирует структуру базы данных и интерфейс .

**Примеры типовых конфигураций:** «1С:Бухгалтерия 8», «1С:Управление торговлей», «1С:Зарплата и управление персоналом».

### 1.3. Режимы работы

Система работает в двух основных режимах :
1.  **Конфигуратор:** Режим разработчика и администратора. Здесь создаются объекты, пишется код, настраиваются права доступа.
2.  **1С:Предприятие:** Основной режим для конечного пользователя. Здесь вводятся данные, формируются отчеты, выполняются хозяйственные операции.

## 2. Архитектура и клиентские приложения

Современная платформа 1С использует многозвенную архитектуру, что позволяет масштабировать систему от персонального использования до работы крупных холдингов .

### 2.1. Клиентские приложения

В зависимости от задач и условий работы используются разные типы клиентов:
*   **Толстый клиент:** Полнофункциональное приложение. Требует установки на компьютер и скачивания значительного объема данных для обработки (исполняет код на стороне клиента). Используется в основном разработчиками и в офисных сетях.
*   **Тонкий клиент:** Приложение, которое выполняет минимум вычислений на стороне пользователя, перенося основную нагрузку на сервер. Не требует много ресурсов и может работать через интернет.
*   **Веб-клиент:** Работает в браузере (Chrome, Edge, Firefox). Не требует установки на компьютер, доступ осуществляется по ссылке. Удобен для удаленной работы.

**Важно:** Тонкий и веб-клиенты работают только с **управляемыми формами**. Толстый клиент может работать как с обычными, так и с управляемыми формами .

### 2.2. Сервер и база данных

Сервер 1С (кластер серверов) выполняет основную бизнес-логику (расчеты, проведение документов). Данные хранятся в СУБД (Системе Управления Базами Данных), такой как MS SQL Server, PostgreSQL или файловая база (для небольших объемов) .

## 3. Объекты конфигурации (Метаданные)

Все элементы прикладного решения создаются из «прототипов» — объектов конфигурации. Каждый объект имеет строго определенную роль. Рассмотрим основные из них.

### 3.1. Справочники

**Определение:** Объект для хранения условно-постоянной информации, списки однородных элементов (например, список сотрудников, номенклатура товаров, контрагенты).

**Ключевые свойства:**
*   **Иерархия:** Справочники могут быть многоуровневыми (например, товары группируются по категориям). Группы и элементы образуют дерево.
*   **Реквизиты:** Дополнительные поля для описания элемента (ИНН, адрес, артикул).
*   **Подчиненность:** Справочник может быть подчинен другому справочнику (например, справочник «Договоры» подчинен справочнику «Контрагенты»).

### 3.2. Документы

**Определение:** Объект для регистрации событий (хозяйственных операций) в хронологическом порядке. Документ всегда имеет дату и номер.

**Ключевое свойство — Проведение:**
Документ не просто хранит данные (как справочник). При проведении документ может создавать **движения** в регистрах. Например, документ «Приходная накладная» при проведении увеличивает остаток товара на складе в регистре накопления.

**Виды:** Документы могут быть с табличными частями (например, список товаров в накладной).

### 3.3. Регистры

Регистры — это объекты, которые хранят оперативные данные в определенном разрезе (аналитике). Они делятся на два основных типа, которые важно различать:

| Характеристика | Регистр сведений | Регистр накопления |
| :--- | :--- | :--- |
| **Назначение** | Хранение статичной или справочной информации | Накопление количественных показателей (остатки, обороты) |
| **Данные** | Курсы валют, тарифы, цены, настройки | Товары на складе, деньги в кассе, взаиморасчеты |
| **Механизм** | Просто запись значений по измерениям | Движения (Приход/Расход), на основе которых считаются остатки |
| **Пример** | Регистр «Курсы валют» (значение курса на дату) | Регистр «ТоварыНаСкладах» (остаток товара) |

**Структура регистра:**
*   **Измерения:** Разрезы, в которых ведется учет (Склад, Номенклатура, Валюта).
*   **Ресурсы:** Числовые показатели, которые накапливаются (Количество, Сумма).
*   **Реквизиты:** Дополнительная информация о записи (Комментарий).

Регистр накопления имеет таблицу движений (первичные данные) и таблицу итогов (для быстрого расчета остатков) .

### 3.4. Отчеты и Обработки

*   **Отчет:** Объект для выборки и представления данных из базы в удобном виде (сводки, графики). Данные для отчета получаются с помощью **системы компоновки данных (СКД)** или запросов.
*   **Обработка:** Объект для выполнения сервисных действий (закрытие месяца, загрузка данных из файла, автоматическое заполнение документов).

## 4. Встроенный язык и механизмы работы

### 4.1. Контекст и модули

**Контекст** — это совокупность доступных в данный момент выполнения кода объектов, переменных и методов. Код пишется в **модулях**.

*   **Модуль объекта:** Выполняется на сервере при обращении к объекту (например, при записи документа).
*   **Модуль формы:** Отвечает за интерактивность (нажатия кнопок, ввод данных). Содержит обработчики событий формы (например, `ПриОткрытии`, `ПриЗаписи`).
*   **Общий модуль:** Библиотека функций, доступных из любого места конфигурации. Служит для повторного использования кода.

### 4.2. Язык запросов и виртуальные таблицы

Для получения данных из базы используется язык запросов, похожий на SQL, но с особенностями 1С.

**Виртуальные таблицы** — это мощный механизм, который позволяет получать уже обработанные данные (например, остатки на дату или обороты за период) без написания сложных алгоритмов.

*   Пример: `РегистрНакопления.ТоварыНаСкладах.Остатки(&Дата, Склад = &Склад)`.
*   **Важное правило:** Условия отбора (например, по конкретному складу) нужно передавать **в параметры виртуальной таблицы**, а не в секцию `ГДЕ` запроса. Это критически влияет на производительность, так как платформа сможет сразу выбрать нужные данные, а не рассчитывать остатки по всей базе, а потом фильтровать результат .

---

## 5. Резюме

1.  **1С** = **Платформа** (движок и конструктор) + **Конфигурация** (прикладное решение).
2.  В основе конфигурации лежат **метаданные** — описание объектов (Справочники, Документы, Регистры).
3.  **Справочники** хранят постоянную информацию, **Документы** фиксируют события и создают **движения** в **Регистрах**.
4.  **Регистры накопления** хранят количественные остатки, **Регистры сведений** — справочные данные.
5.  Логика работы описывается на **встроенном языке** в модулях, а данные извлекаются через **запросы** с использованием **виртуальных таблиц**.
