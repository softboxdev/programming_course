## 📚 Теоретическая справка (прочитай перед началом)

### Что такое SQLite и почему с него начинают

SQLite — это **встроенная** (embedded) база данных. В отличие от MySQL или PostgreSQL, ей **не нужен отдельный сервер**. Вся база данных — это **один файл** на диске (обычно с расширением `.db` или `.sqlite`). Когда программа открывает этот файл, она получает полный доступ ко всем таблицам и данным внутри.

Это идеальный вариант для обучения: не нужно устанавливать сервер, настраивать пользователей и пароли. Просто создаёшь файл — и работаешь.

### Что такое DDL

**DDL (Data Definition Language)** — это команды SQL, которые **определяют структуру** базы данных, а не работают с данными внутри неё. К DDL относятся:

- `CREATE TABLE` — создать таблицу
- `ALTER TABLE` — изменить структуру таблицы
- `DROP TABLE` — удалить таблицу

В этой работе мы используем именно DDL, потому что создаём «каркас» — таблицу, а не заполняем её данными.

### Что такое транзакция и зачем commit

**Транзакция** — это группа операций с базой данных, которая выполняется как единое целое. Представь, что ты переводишь деньги с одной карты на другую: нужно, чтобы списание с первой и зачисление на вторую произошли **вместе**. Если что-то пойдёт не так — обе операции отменяются, и деньги остаются на месте.

В SQLite (и большинстве СУБД) действует правило: **изменения не сохраняются на диск, пока ты не вызовешь `commit()`**. Пока commit не вызван, изменения «висят» в памяти и могут быть отменены (rollback). Это защита от ошибок.

Ключевая аналогия:
- `execute()` — «записал в черновик»
- `commit()` — «подписал и отправил в дело»
- `rollback()` — «порвал черновик»

Для DDL-операций (создание таблицы) это тоже работает: если не сделать `commit()`, таблица не появится в файле базы данных навсегда.

### Разница между `connect()` и `cursor()`

- **Соединение (`connection`)** — это «канал связи» с файлом базы данных. Через него выполняется commit и rollback.
- **Курсор (`cursor`)** — это «рука», которая выполняет конкретные SQL-запросы. Курсор создаётся **из соединения**.

Схема: `sqlite3.connect() → connection → connection.cursor() → cursor → cursor.execute(SQL)`

## 🎯 Пошаговая инструкция выполнения

### Шаг 1. Подготовка рабочей папки

Создай папку для проекта, например `task_manager`. Внутри неё будет лежать наш скрипт и (после запуска) файл базы данных.

```
task_manager/
└── init_db.py   ← пока пустой, создадим дальше
```

Открой папку в редакторе кода (VS Code, PyCharm, Sublime Text — любой).

> **Почему это важно:** файл `app.db` будет создан в той папке, из которой запускается скрипт. Если запустить скрипт из другого места, база создастся там, и ты будешь искать её в неправильном месте.

### Шаг 2. Проверка наличия модуля sqlite3

Модуль `sqlite3` **входит в стандартную библиотеку Python**, поэтому устанавливать его через pip не нужно. Проверь версию Python:

```bash
python --version
```

Если версия 3.6+ — всё в порядке. Модуль уже есть.

### Шаг 3. Написание скрипта `init_db.py`

Открой файл `init_db.py` и внеси следующий код. Ниже — полный скрипт с комментариями, объясняющими каждую строку.

```python
import sqlite3

# ---------- 1. ПОДКЛЮЧЕНИЕ ----------
# Если файла app.db нет — он будет создан автоматически.
# Если есть — подключение произойдёт к существующему файлу.
conn = sqlite3.connect('app.db')

# ---------- 2. СОЗДАНИЕ КУРСОРА ----------
# Через курсор мы будем отправлять SQL-команды в базу.
cursor = conn.cursor()

# ---------- 3. ВЫПОЛНЕНИЕ DDL ----------
# Создаём таблицу tasks (задачи) с тремя колонками.
# IF NOT EXISTS — защита от ошибки, если таблица уже существует:
#   при повторном запуске скрипта ошибки не будет.
#
# Разбор колонок:
#   id     INTEGER PRIMARY KEY — целое число, уникальный идентификатор строки.
#                                SQLite автоматически заполняет его (1, 2, 3...).
#   title  TEXT NOT NULL       — текст, обязательное поле (нельзя оставить пустым).
#   status TEXT DEFAULT 'new'  — текст; если значение не передано,
#                                автоматически ставится 'new' (новая задача).
cursor.execute("""
    CREATE TABLE IF NOT EXISTS tasks (
        id     INTEGER PRIMARY KEY,
        title  TEXT NOT NULL,
        status TEXT DEFAULT 'new'
    )
""")

# ---------- 4. ФИКСАЦИЯ (COMMIT) ----------
# КРИТИЧЕСКИ ВАЖНЫЙ ШАГ.
# Без commit() структура таблицы останется только в памяти
# и НЕ будет записана в файл app.db.
# Если закрыть соединение без commit — таблица исчезнет.
conn.commit()

# ---------- 5. ЗАКРЫТИЕ СОЕДИНЕНИЯ ----------
# Освобождает файл базы данных.
# Если не закрыть — файл может остаться заблокированным
# для других программ (например, для DB Browser for SQLite).
conn.close()

print("База данных и таблица tasks успешно созданы.")
```

### Шаг 4. Запуск скрипта

В терминале, находясь в папке `task_manager`, выполни:

```bash
python init_db.py
```

Ожидаемый вывод:

```
База данных и таблица tasks успешно созданы.
```

### Шаг 6. Проверка структуры базы (рекомендуется)

Чтобы убедиться, что таблица действительно создалась, можно:

**Вариант А — через Python (быстрый способ):**

Создай файл `check_db.py`:

```python
import sqlite3

conn = sqlite3.connect('app.db')
cursor = conn.cursor()

# Запрос к системной таблице sqlite_master,
# где SQLite хранит список всех таблиц.
cursor.execute("SELECT name FROM sqlite_master WHERE type='table'")
tables = cursor.fetchall()

print("Таблицы в базе:", tables)

conn.close()
```

Запусти: `python check_db.py`. Ожидаемый вывод:

```
Таблицы в базе: [('tasks',)]
```

**Вариант Б — через визуальный инструмент (наглядно):**

Скачай бесплатную программу **DB Browser for SQLite** (https://sqlitebrowser.org/). Открой в ней файл `app.db` — увидишь таблицу `tasks` и её колонки в графическом интерфейсе. Это полезный навык: так ты будешь проверять базу на протяжении всего курса.

### Шаг 7. Проверка идемпотентности (важный эксперимент)

Запусти `init_db.py` **второй раз**. Что произойдёт?

- Ошибки **не будет**, потому что мы использовали `IF NOT EXISTS`.
- Таблица не создастся заново, останется прежняя.

Это называется **идемпотентностью** — свойство скрипта, при котором повторный запуск не меняет результат. Хорошая практика: init-скрипты должны быть идемпотентными.

**Эксперимент:** убери `IF NOT EXISTS` из запроса и запусти скрипт второй раз. Ты получишь ошибку:

```
sqlite3.OperationalError: table tasks already exists
```

Верни `IF NOT EXISTS` обратно — это правильный вариант.

## ⚠️ Типичные ошибки новичков

| Ошибка | Причина | Решение |
|---|---|---|
| `sqlite3.OperationalError: table tasks already exists` | Запуск скрипта без `IF NOT EXISTS` повторно | Добавить `IF NOT EXISTS` в `CREATE TABLE` |
| Файл `app.db` не появился | Скрипт запущен из другой папки | Запускать из папки проекта; проверить `pwd` / `cd` |
| `database is locked` | Не вызван `conn.close()` в предыдущем запуске | Всегда закрывать соединение; перезапустить терминал |
| Таблица создалась, но пропала после перезапуска Python | Забыт `conn.commit()` | Добавить `commit()` **перед** `close()` |
| `IndentationError` | Неправильные отступы в Python | Использовать 4 пробела, не табы |
