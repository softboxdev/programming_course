# Практическая работа №4: Интеграция Flask и SQLite (Чтение данных)

## 📚 Теоретическая справка

### Что такое шаблоны Jinja2 и зачем они нужны

В Практической работе №3 мы возвращали HTML прямо из Python-функции в виде строки. Это работает, но у подхода есть серьёзные проблемы:
- HTML и Python-код перемешаны — читать и править неудобно;
- нельзя переиспользовать куски страницы (шапку, меню);
- редактор не подсвечивает HTML-синтаксис внутри строки Python.

**Jinja2** — шаблонизатор, встроенный во Flask. Идея простая: HTML живёт в отдельном файле `.html`, а Python-код **вставляет** в него данные в нужные места. Шаблон — это HTML с «дырками», которые заполняются при рендеринге.

Схема:

```
Python-функция (view)  →  render_template('index.html', items=rows)  →  Jinja2 подставляет данные в HTML  →  готовый HTML  →  браузер
```

### Основной синтаксис Jinja2

В шаблоне используются специальные «скобки»:

| Синтаксис | Что делает | Пример |
|---|---|---|
| `{{ ... }}` | Вывести значение (экранируется автоматически) | `{{ item.title }}` |
| `{% ... %}` | Управляющая конструкция (цикл, условие) | `{% for item in items %}` |
| `{# ... #}` | Комментарий (в HTML не попадёт) | `{# список задач #}` |

Пример цикла в шаблоне:

```html
<ul>
{% for item in items %}
    <li>{{ item.title }}</li>
{% endfor %}
</ul>
```

### Что такое `render_template`

Функция Flask `render_template('index.html', items=rows)` делает две вещи:
1. Находит файл `templates/index.html`.
2. Прогоняет его через Jinja2, подставляя переменные, переданные именованными аргументами (`items=rows` — в шаблоне доступна переменная `items`).

Возвращает готовую HTML-строку, которую Flask отправляет браузеру.

> **Важно:** файл должен лежать именно в папке `templates/`, иначе Flask его не найдёт.

### Что такое `sqlite3.Row` и зачем он нужен

По умолчанию `cursor.fetchall()` возвращает список **кортежей**:

```python
[('Купить хлеб', 'new'), ('Сделать уроки', 'done')]
```

Обращаться к ним можно только по индексу: `row[0]`, `row[1]`. Это неудобно и легко ошибиться (забудешь, что `0` — это title, а не id).

Если установить `conn.row_factory = sqlite3.Row`, строки становятся **объектами с доступом по имени колонки**:

```python
row['title']   # вместо row[0]
row['status']  # вместо row[2]
```

В шаблоне это критично: `{{ item.title }}` работает только с `sqlite3.Row`, а `{{ item[0] }}` — с кортежем. Мы будем использовать `sqlite3.Row` — так код читается лучше.

### Последовательность транзакций при чтении

При чтении данных (SELECT) `commit()` **не нужен** — данные не меняются. Последовательность:

```
подключение → cursor → execute(SELECT) → fetchall → close → передача в шаблон
```

Соединение закрываем **до** рендеринга шаблона — данные уже в памяти, база больше не нужна.

### Шаг 2. Создание шаблона `templates/index.html`

Создай файл `templates/index.html`:

```html
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <title>Список задач</title>
    <style>
        body { font-family: Arial, sans-serif; max-width: 700px; margin: 40px auto; }
        h1 { color: #333; }
        ul { list-style: none; padding: 0; }
        li { padding: 10px; margin: 6px 0; background: #f4f4f4; border-radius: 6px; }
        .done { text-decoration: line-through; color: #888; }
        .empty { color: #999; font-style: italic; }
    </style>
</head>
<body>
    <h1>Мой список задач</h1>

    {% if items %}
        <ul>
            {% for item in items %}
                <li class="{% if item.status == 'done' %}done{% endif %}">
                    <strong>#{{ item.id }}</strong>
                    {{ item.title }}
                    <em>[{{ item.status }}]</em>
                </li>
            {% endfor %}
        </ul>
    {% else %}
        <p class="empty">Список пуст. Добавь первую задачу!</p>
    {% endif %}
</body>
</html>
```

**Разбор шаблона:**
- `{% if items %}` — проверка, есть ли данные. Если список пуст — показываем сообщение.
- `{% for item in items %}` — цикл по строкам.
- `{{ item.id }}`, `{{ item.title }}` — доступ к полям по имени (работает с `sqlite3.Row`).
- `{% if item.status == 'done' %}done{% endif %}` внутри атрибута `class` — условная подстановка CSS-класса. У выполненных задач будет зачёркнутый текст.

### Шаг 3. Переписываем `app.py`: чтение из базы

Открой `app.py` и приведи его к виду:

```python
import sqlite3
from flask import Flask, render_template

app = Flask(__name__)

DB_PATH = 'app.db'


def get_connection():
    """Открывает соединение с базой и настраивает доступ к полям по имени."""
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row   # ← строки станут sqlite3.Row
    return conn


@app.route('/')
def index():
    # 1. Подключение
    conn = get_connection()
    cursor = conn.cursor()

    # 2. SELECT
    cursor.execute("SELECT id, title, status FROM tasks ORDER BY id")
    rows = cursor.fetchall()

    # 3. Закрытие (commit не нужен — данных не меняем)
    conn.close()

    # 4. Передача в шаблон
    return render_template('index.html', items=rows)


if __name__ == '__main__':
    app.run(debug=True, port=5000)
```

Обрати внимание:
- `render_template` импортируется из `flask`.
- `conn.row_factory = sqlite3.Row` — ставим **сразу после connect**, до курсора.
- `rows` передаём в шаблон под именем `items`. В шаблоне переменная называется `items`.

### Шаг 5. Проверка «живой» связи с базой

Не останавливая сервер:

1. В **другом терминале** запусти `python crud_console.py`.
2. Добавь новую задачу, например `Проверка связи`.
3. Вернись в браузер, обнови страницу.
4. Новая задача **появилась** — значит, Flask читает актуальные данные из того же файла `app.db`.

Это наглядная демонстрация: база — это общий файл, к которому обращаются разные программы.

### Шаг 6. Проверка пустой базы

Удали все задачи через `crud_console.py` (или напрямую через DB Browser). Обнови страницу — увидишь «Список пуст. Добавь первую задачу!». Это сработала ветка `{% else %}` в Jinja2.

Верни пару задач обратно.

### Шаг 7. Эксперимент: `sqlite3.Row` vs обычный кортеж

Убери строку `conn.row_factory = sqlite3.Row` из `get_connection()` и обнови страницу. Ты получишь ошибку:

```
jinja2.exceptions.UndefinedError: 'sqlite3.Row object has no attribute...'
```

Точнее, Jinja2 попытается обратиться к `item.title`, но получит кортеж — и `item.title` не сработает. Верни `row_factory` назад. Это доказывает, зачем он нужен.

**Альтернатива без `row_factory`:** в шаблоне писать `{{ item[1] }}` вместо `{{ item.title }}`. Но это плохо читается и ломается при изменении порядка колонок в SELECT. Поэтому `row_factory` — правильный выбор.

## ⚠️ Типичные ошибки

| Ошибка | Причина | Решение |
|---|---|---|
| `TemplateNotFound: index.html` | Шаблон лежит не в `templates/` или имя с опечаткой | Проверь папку и имя файла (регистр важен: `Index.html` ≠ `index.html`) |
| `UndefinedError: 'sqlite3.Row object has no attribute ...'` | Не установлен `row_factory` | Добавь `conn.row_factory = sqlite3.Row` после connect |
| `jinja2.exceptions.UndefinedError: 'items' is undefined` | Забыл передать `items=rows` в `render_template` | Проверь вызов `render_template('index.html', items=rows)` |
| Страница пустая, но задач в базе много | SELECT вернул 0 строк (опечатка в имени таблицы) | Проверь SQL; запусти запрос через DB Browser |
| Данные не обновляются после добавления из консоли | Flask открыл другое соединение к другой базе | Проверь, что оба скрипта используют один и тот же путь `app.db` |
| `OperationalError: no such table: tasks` | База есть, но таблицы нет (работа №1 не выполнена) | Запусти `init_db.py` |
