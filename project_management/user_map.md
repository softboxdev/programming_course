Самостоятельное задание по теме «Создание карты пользовательских историй» (User Story Mapping)
Цель задания

Освоить методику построения карты пользовательских историй (User Story Map) для визуализации и приоритизации требований к продукту.
Исходная ситуация

Вы — аналитик/продакт-менеджер в команде, которая разрабатывает цифровой продукт. Руководство поставило задачу: спланировать первую версию продукта (MVP) и определить очередность разработки функций.

Выберите один продукт (или предложите свой):

    Мобильное приложение для заказа кофе с самовывозом.

    Сервис онлайн-бронирования коворкингов.

    Платформа для поиска репетиторов.

    Приложение для учета личных финансов.

    Веб-сервис для организации волонтерских мероприятий.

Задание (выполняется индивидуально)
Шаг 1. Определите пользователей и их цели

    Опишите 2–3 типа пользователей (персоны): кто они, какие задачи решают.

    Сформулируйте главную цель каждого пользователя при взаимодействии с продуктом.

Шаг 2. Постройте «скелет» карты

    Определите 5–7 ключевых этапов пользовательского пути (activities) — крупные шаги, которые проходит пользователь для достижения цели (например: «Выбор товара → Оформление заказа → Оплата → Получение»).

    Разместите этапы горизонтально — это верхний уровень карты.

Шаг 3. Декомпозируйте этапы на пользовательские истории

Для каждого этапа сформулируйте 2–4 пользовательские истории в формате:

    «Как [роль], я хочу [действие], чтобы [ценность/цель]».

Истории разместите вертикально под соответствующим этапом (от более важных к менее важным).
Шаг 4. Выделите MVP (минимально жизнеспособный продукт)

    Проведите горизонтальную линию, отделяющую истории, без которых продукт не решает основную задачу пользователя.

    Обоснуйте, почему выбранные истории вошли в MVP, а остальные — нет.

Шаг 5. Спланируйте релизы

    Разбейте истории ниже линии MVP на 2–3 релиза (итерации).

    Для каждого релиза укажите, какую дополнительную ценность он дает пользователю.

Шаг 6. Приоритизируйте истории

Используйте один из методов (на выбор):

    MoSCoW (Must / Should / Could / Won't);

    Матрица ценность/сложность — распределите истории по квадрантам;

    RICE (Reach, Impact, Confidence, Effort) — рассчитайте балл для 5–7 ключевых историй.

Шаг 7. Оформите результат

Подготовьте карту в любом удобном инструменте:

    Excel (скриншот доски);

    Weeek (скриншот доски);

    таблица Excel/Google Sheets;

    рисунок от руки (фото/скан) — приветствуется креативность.

Требования к результату
Критерий	Баллы
Описаны персоны и их цели	10
Выделено 5–7 этапов пользовательского пути	10
Сформулировано не менее 15 пользовательских историй в правильном формате	20
Корректно выделен MVP с обоснованием	15
Истории распределены по релизам с описанием ценности	15
Применен метод приоритизации, результаты аргументированы	15
Оформление карты (наглядность, читаемость)	10
Презентация/защита работы (3–5 минут)	5
Итого	100
Минимум 60 баллов (оценка 3)

Форма сдачи 

    Файл с картой (электронная таблица в формате Excel).

    Краткая пояснительная записка (1–2 листы Excel): персоны, обоснование MVP, логика релизов и приоритизации.
    
    Все файлы при сдаче на почту a.kondybayeva@yandex.ru должны быть подписаны в теме письма ФИО_ГРУППА_НАЗВАНИЕ_РАБОТЫ, в теле письма прилагается перечень файлов.

    Устная защита — ответы на вопросы: «Почему эта история в MVP?», «Что произойдет, если убрать историю X?», «Как вы проверяли ценность историй?».

Критерии оценки (шкала)

    90–100 — карта полная, логичная, MVP убедительно обоснован, приоритизация аргументирована.

    75–89 — карта построена верно, есть небольшие пробелы в обосновании или оформлении.

    60–74 — основные элементы есть, но нарушена логика этапов/приоритетов, слабая аргументация.

    Менее 60 — задание выполнено фрагментарно, формат историй не соблюден, MVP не выделен.

Дополнительно (для продвинутых)

    Добавьте к каждой истории критерии приемки (Acceptance Criteria) в формате Given-When-Then.

    Проведите «разрез» карты (release slicing) так, чтобы каждый релиз был демонстрируемым конечному пользователю.

    Оцените истории в story points и сформируйте план на 2 спринта.
