# Самостоятельная (практическая) работа по теме «Приоритизация задач и анализ результатов»

## Цель работы
Освоить методы приоритизации задач/требований и научиться анализировать результаты приоритизации: обосновывать решения, выявлять риски и корректировать план работ.

## Исходная ситуация
Вы — аналитик / продакт-менеджер / тимлид в команде, разрабатывающей цифровой продукт. На вход поступил **бэклог из 12–15 задач** (фич, баг-фиксов, технических улучшений) от разных стейкхолдеров. Ресурсы команды ограничены: в ближайший спринт/квартал можно взять только часть задач. Нужно расставить приоритеты и проанализировать последствия принятых решений.

**Выберите один продукт (или предложите свой):**
1. Мобильное приложение для заказа кофе с самовывозом.
2. Сервис онлайн-бронирования коворкингов.
3. Платформа для поиска репетиторов.
4. Приложение для учёта личных финансов.
5. Веб-сервис для организации волонтёрских мероприятий.

> 💡 Рекомендуется использовать продукт, по которому вы уже строили карту пользовательских историй (предыдущая работа), — так вы получите сквозной кейс.

## Задание (индивидуально)

### Шаг 1. Сформируйте исходный бэклог
- Составьте список из **12–15 задач** (пользовательские истории, фичи, баги, техдолг, инфраструктурные задачи).
- Для каждой задачи укажите:
  - краткое описание;
  - источник/заказчика (кто просит и зачем);
  - ожидаемую ценность для пользователя/бизнеса;
  - предварительную оценку трудозатрат (в story points, человеко-днях или условных единицах).

### Шаг 2. Выберите и примените методы приоритизации
Примените **минимум два** метода из списка (лучше — три, чтобы сравнить результаты):

1. **MoSCoW** — распределите все задачи по категориям Must / Should / Could / Won't.
2. **Матрица «Ценность/Сложность» (Value vs Effort)** — разместите задачи по квадрантам (Quick Wins, Big Bets, Fill-ins, Money Pit).
3. **RICE** — рассчитайте балл: `RICE = (Reach × Impact × Confidence) / Effort` для каждой задачи.
4. **Метод взвешенных критериев (Scoring Model)** — задайте 4–5 критериев (например: ценность для бизнеса, ценность для пользователя, риск, трудозатраты, стратегическая важность), веса и оценки по шкале 1–5.
5. **Kano-модель** — классифицируйте задачи как базовые (Must-be), производительные (Performance), восхищающие (Delighters), безразличные и обратные.

### Шаг 3. Сравните результаты разных методов
- Сведите результаты в единую таблицу.
- Выделите **топ-5 задач**, которые попали в приоритет по результатам **всех** применённых методов (зона уверенности).
- Отметьте **задачи-конфликты**, по которым методы дали противоположные результаты (например, высокая ценность, но очень высокая сложность).
- Объясните, почему возникли расхождения.

### Шаг 4. Сформируйте итоговый приоритизированный список
- Составьте финальный ранжированный список задач (1, 2, 3 … N) с обоснованием.
- Определите, какие задачи попадают в **ближайший спринт/релиз** (с учётом ограничения по ёмкости команды — например, не более 20 story points).
- Укажите, какие задачи откладываются и при каких условиях к ним вернутся.

### Шаг 5. Проанализируйте результаты приоритизации
Ответьте письменно на вопросы:
1. Какие задачи оказались в MVP/спринте и почему? Какие — за бортом и почему?
2. Какие **риски** несёт выбранный приоритет? (например: пропуск критичного бага, недовольство стейкхолдера, накопление техдолга).
3. Какие **компромиссы** пришлось сделать? Кого из стейкхолдеров затронуло решение?
4. Какие задачи могут «взорваться», если их откладывать слишком долго (техдолг, юридические/регуляторные требования, безопасность)?
5. Как изменится приоритет, если изменится контекст: сокращение бюджета на 30%, появление нового конкурента, требование регулятора, крупный клиент с новым требованием?
6. Какие **метрики** вы будете отслеживать, чтобы проверить, что приоритизация была верной? (например: retention, конверсия, NPS, количество багов, скорость доставки).

### Шаг 6. Проведите «пересмотр приоритетов» (re-prioritization)
- Смоделируйте изменение вводных (на выбор или по заданию преподавателя):
  - резко выросла нагрузка на поддержку из-за багов;
  - появился новый крупный заказчик с жёстким дедлайном;
  - команда потеряла одного разработчика (ёмкость -25%);
  - регулятор ввёл новое требование.
- Пересмотрите приоритеты с учётом нового контекста и опишите, что изменилось и почему.

### Шаг 7. Оформите результат
Подготовьте:
- **таблицу бэклога** с оценками и результатами по каждому методу;
- **итоговый приоритизированный список** с обоснованием;
- **краткую аналитическую записку** (1–2 страницы) с выводами и ответами на вопросы Шага 5;
- **визуализацию** (матрица ценность/сложность, диаграмма RICE-баллов или Kano-график) — в Excel/Google Sheets, Miro, FigJam и т. п.

## Требования к результату
| Критерий | Баллы |

| Корректно применён первый метод приоритизации | 10 |
| Корректно применён второй метод приоритизации | 10 |
| Проведено сравнение методов, выявлены совпадения и конфликты, объяснены расхождения | 15 |
| Сформирован итоговый ранжированный список с обоснованием | 10 |
| Учтено ограничение ёмкости команды при выборе задач в спринт | 5 |
| Проведён содержательный анализ результатов (риски, компромиссы, метрики) | 15 |

## Форма сдачи
1. Файл с таблицей бэклога и расчётами (Excel/Google Sheets) или ссылка на доску.
2. Аналитическая записка (1–2 страницы).
3. Визуализация (матрица/диаграмма).
4. Устная защита — ответы на вопросы: «Почему задача X в топе, а Y — нет?», «Что будет, если отложить задачу Z на 2 спринта?», «Какой метод вы считаете наиболее надёжным в вашем кейсе и почему?».

## Критерии оценки (шкала)
- **90–100** — бэклог полный и реалистичный, применены 2–3 метода, сравнение аргументировано, анализ результатов глубокий (риски, компромиссы, метрики), пересмотр приоритетов продуман.
- **75–89** — методы применены верно, итоговый список обоснован, но анализ результатов поверхностный или пересмотр приоритетов формальный.
- **60–74** — приоритизация выполнена, но сравнение методов слабое, анализ результатов фрагментарный, есть ошибки в расчётах.
- **Менее 60** — применён только один метод без анализа, итоговый список не обоснован, отсутствует анализ результатов.

## Дополнительно (для продвинутых)
- Добавьте **WSJF** (Weighted Shortest Job First) — расчёт `Cost of Delay / Job Size` — и сравните с RICE.
- Постройте **матрицу рисков** отложенных задач (вероятность × влияние).
- Проведите **ретроспективу приоритизации**: что команда узнала, какие гипотезы о ценности подтвердились/опроверглись.
- Смоделируйте **два сценария** распределения ёмкости (например, 70% фичи / 30% техдолг vs 50/50) и сравните последствия.
