## Этап 2. Анализ требований и ТЗ

**Результат:** раздел «Техническое задание» в пояснительной записке.

**Что включить:**
- **Цель и задачи.** Зачем приложение, какие проблемы решает.
- **Функциональные требования.** Что умеет приложение: CRUD (создание, чтение, обновление, удаление) сущностей, расчёты, отчёты/экспорт, поиск/фильтрация.
- **Нефункциональные требования.** Производительность (время отклика/расчёта), удобство интерфейса, переносимость (ОС), безопасность (если есть учётные записи), тестируемость.
- **Роли и права.** Если пользователей несколько (администратор/обычный пользователь).
- **Сценарии использования (Use Cases).** Кратко: «Пользователь создаёт блюдо», «Система рассчитывает норму расхода».
- **Ограничения.** Технологии (язык, фреймворк), формат экспорта (PDF, CSV, Excel), требования к ОС.

**Совет:** оформите требования таблицей: «Функция — Описание — Приоритет — Статус».

## Этап 3. Проектирование архитектуры и модели данных (2–3 недели)

### Архитектура
Опишите компоненты и связи:
- **Тип приложения:** десктоп (GUI), веб, консольное (для учебных расчётов).
- **Стек технологий:**  язык, который выбрали (C#, Java, Python, C++), фреймворк/библиотека (WPF, Swing, PyQt, Electron, ASP.NET, Django, FastAPI), СУБД (SQLite, PostgreSQL, MySQL) или файлы (JSON, CSV).
- **Структура модулей:** разделение на слои (интерфейс, логика, данные), отдельные классы/сервисы для расчётов и отчётов.
- **Инструменты:** IDE, система контроля версий (Git), средства сборки/упаковки (если есть).

### Модель данных
- **Сущности и атрибуты.** Например, для темы 6 (дерево Хаффмена): `symbols(char, frequency)`, `tree_nodes(parent_id, left_child, right_child, symbol, code)`.
- **Диаграмма классов UML.** Покажите классы, атрибуты, методы, связи (наследование, агрегация).
- **Схема БД (если используется).** ER‑диаграмма, типы данных, первичные/внешние ключи, индексы, ограничения.
- **Форматы обмена.** JSON/XML для импорта/экспорта, CSV для отчётов, PDF для печатных форм.

**Чек‑лист:**
- [ ] Диаграмма классов готова.
- [ ] ER‑диаграмма (если есть БД) готова.
- [ ] Описаны форматы ввода/вывода.
- [ ] Продумана обработка ошибок и граничных случаев (деление на ноль, пустые поля, неверный формат).

## Этап 5. Реализация 

Разбейте на итерации по 1–2 недели:

1. **Настройка проекта.** Git, структура папок, зависимости, переменные окружения.
2. **Модель данных и хранение.** Классы/таблицы, миграции, начальные тестовые данные.
3. **Базовая логика.** CRUD, простые расчёты, валидация входных данных.
4. **Расчётные модули.** Для тем 2–5 — реализация численных методов с контролем точности и числа итераций. Для темы 6 — построение дерева Хаффмена, кодирование/декодирование.
5. **Интерфейс.** Связка UI с логикой, обработка событий, отображение результатов.
6. **Отчётность и экспорт.** Формирование отчётов (CSV, PDF), печать форм, сохранение результатов.
7. **Тестирование.** Юнит‑тесты для расчётных функций, тесты интерфейса (если возможно).

**Примеры стеков:**
- Python + PyQt/Tkinter + SQLite + pytest.
- C# + WPF + Entity Framework + xUnit.
- Java + Swing/JavaFX + H2/PostgreSQL + JUnit.

**Важно:** используйте систему контроля версий, пишите комментарии к сложным расчётам, делайте понятные коммиты.

## Этап 6. Тестирование и отладка

**Виды тестов:**
- **Юнит‑тесты.** Проверка отдельных функций (расчёт нормы, построение дерева, численный метод).
- **Интеграционные тесты.** Сценарий: ввод → расчёт → вывод → экспорт.
- **Тестовые данные.** Крайние случаи (нулевые значения, большие числа, некорректный ввод), типовые сценарии.

**Метрики для отчёта:**
- Покрытие тестами (если есть инструмент).
- Количество найденных и исправленных багов.
- Время выполнения расчётов (для тем 2–5, 6).

**Чек‑лист готовности:**
- [ ] Приложение запускается на целевой ОС.
- [ ] Все функции из ТЗ реализованы.
- [ ] Нет критических ошибок (деление на ноль, падение при пустом вводе).
- [ ] Есть тестовые сценарии и результаты.

**Структура записки:**

2. Введение: актуальность, цель, задачи, объект и предмет.
3. Анализ предметной области: описание задачи, обзор аналогов, обоснование выбора темы.
4. Техническое задание: функциональные и нефункциональные требования, роли, Use Cases.
5. Проектирование: архитектура, диаграмма классов, схема БД, прототипы UI.
6. Реализация: описание модулей, ключевые фрагменты кода, скриншоты интерфейса.
7. Тестирование: методика, тестовые сценарии, результаты, найденные баги.
8. Заключение: что сделано, что можно улучшить.
9. Список литературы и приложения (код, SQL‑скрипты, примеры отчётов).

**Особые акценты по группам тем:**
- Темы 2–5: приведите формулы, опишите алгоритм численного метода, покажите пример расчёта «вручную» и сравнение с результатом программы.

- Темы с планированием/учётом (8, 9, 10, 19 и др.): опишите логику расчёта (например, как формируется график работ, как считается остаток на складе), приведите пример входных данных и итоговый отчёт.
